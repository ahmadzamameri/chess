# ♟️ شطرنج أونلاين (Client + Server)

لعبة شطرنج مباشرة بين لاعبين حقيقيين عبر Socket.IO. المستخدم يكتب اسمًا مؤقتًا،
يضغط **العب الآن**، فيربطه السيرفر تلقائيًا بأول منافس متاح، ويختار الألوان عشوائيًا،
ثم تبدأ المباراة فورًا. **السيرفر هو المرجع الوحيد لقانونية النقلات** (عبر `chess.js`)،
والعميل يعرض فقط ولا يُوثق به.

---

## المتطلبات

- **Node.js 18+** (يُفضّل 20+).
- **npm** (يأتي مع Node).
- نظام Windows / macOS / Linux (طُوِّر واختُبر على Windows).

---

## البنية

```
admin-app/
├─ server/   ← Express + Socket.IO + chess.js (منطق المباراة والمطابقة)
├─ client/   ← React + Vite + react-chessboard (الواجهة)
└─ package.json  ← تشغيل الاثنين معًا عبر concurrently
```

---

## التثبيت

من مجلد `admin-app` (الجذر):

```bash
npm run install:all
```

هذا يثبّت حزم الجذر + السيرفر + الواجهة. (بديل: `npm install` داخل كل من `server` و `client` يدويًا.)

### إعداد ملفات البيئة

انسخ ملفات المثال (لا تحتوي أي أسرار):

```bash
# السيرفر
copy server\.env.example server\.env      # Windows
# cp server/.env.example server/.env      # macOS/Linux

# الواجهة
copy client\.env.example client\.env
```

القيم الافتراضية تعمل محليًا كما هي.

---

## التشغيل

### الطريقة الأسهل — تشغيل الاثنين معًا

من مجلد الجذر:

```bash
npm run dev
```

- السيرفر: <http://localhost:4000>
- الواجهة: <http://localhost:5173>

### أو كلٌّ على حدة

```bash
npm run dev:server   # السيرفر فقط
npm run dev:client   # الواجهة فقط
```

## المنافذ

| الخدمة | المنفذ | يُضبط عبر |
|--------|--------|-----------|
| السيرفر (API + Socket.IO) | `4000` | `server/.env` → `PORT` |
| الواجهة (Vite) | `5173` | `client/vite.config.ts` + `client/.env` → `VITE_SERVER_URL` |

> إن غيّرت منفذ الواجهة، حدّث `CLIENT_ORIGIN` في `server/.env`.
> إن غيّرت منفذ السيرفر، حدّث `VITE_SERVER_URL` في `client/.env`.

## اختبار لاعبين محليًا

1. شغّل `npm run dev`.
2. افتح <http://localhost:5173> في نافذة متصفح عادية.
3. اكتب الاسم **أحمد** واضغط **العب الآن** → تظهر «جارٍ البحث عن منافس…».
4. افتح نافذة **Incognito / خفيّة** على نفس العنوان.
5. اكتب الاسم **محمد** واضغط **العب الآن**.
6. يُربط اللاعبان فورًا وتبدأ المباراة في النافذتين.
7. حرّك قطعة عند من دوره → تظهر النقلة فورًا عند الطرف الآخر.
8. لا يمكن لأي لاعب تحريك قطع خصمه (السيرفر يرفض).
9. جرّب: كش مات، استسلام، عرض تعادل، وإغلاق نافذة (انقطاع + مهلة 30 ثانية).

> **مهم:** استخدم نافذتين مختلفتين (عادية + خفيّة) أو متصفحين مختلفين، لأن معرّف
> الجلسة (`sessionId`) يُخزَّن في `localStorage` لكل متصفح على حدة.

## كيف يعمل (باختصار)

- **المطابقة:** قائمة انتظار في ذاكرة السيرفر (`matchmaking/queue.ts`). أول لاعب ينتظر،
  والثاني يُنشئ مباراة، وتُختار الألوان عشوائيًا.
- **حالة المباراة:** كائن `GameSession` لكل مباراة (FEN + التاريخ + الحالة + عرض التعادل)
  مُدارة عبر `games/gameManager.ts` (في الذاكرة الآن — مفصولة لتسهيل إضافة MySQL لاحقًا).
- **الأمان:** تحقق من كل حدث Socket، الهوية من `sessionId` (لا من العميل)، تنظيف الاسم،
  تحديد معدّل للأحداث، ولا يُرسَل للعميل إلا الحالة العامة.
- **إعادة الاتصال:** عند قطع الاتصال يُمنح اللاعب 30 ثانية للعودة (`rejoin` بالجلسة)؛
  وإلا يُحسم لصالح الخصم.

## أشهر الأخطاء المحتملة

| المشكلة | السبب المحتمل | الحل |
|---------|----------------|------|
| الواجهة لا تتصل / «جارٍ الاتصال بالسيرفر» | السيرفر غير مشغّل أو منفذ خاطئ | تأكد أن السيرفر يعمل على 4000 وأن `VITE_SERVER_URL` صحيح |
| خطأ CORS في الكونسول | `CLIENT_ORIGIN` لا يطابق منفذ الواجهة | اضبط `CLIENT_ORIGIN=http://localhost:5173` في `server/.env` وأعد التشغيل |
| المطابقة لا تحدث | نافذتان بنفس `sessionId` (نفس المتصفح) | استخدم نافذة عادية + Incognito أو متصفحين |
| `EADDRINUSE` | المنفذ مشغول ببرنامج آخر | غيّر `PORT` أو أغلق البرنامج الآخر |
| القطع لا تتحرك | ليس دورك، أو المباراة انتهت | انتظر دورك؛ راجع شريط «دورك/دور المنافس» |
| النقلات تُرفض دائمًا | إصدار `chess.js` مختلف | نفّذ `npm install` داخل `server` من جديد |

## ملاحظات النسخة الأولى

- المباريات تُحفظ في **ذاكرة السيرفر فقط**؛ إعادة تشغيل السيرفر تُنهي المباريات الجارية.
- لا قاعدة بيانات، لا أصدقاء، لا بطولات، لا لوحة إدارة (حسب المطلوب).
- ترقية الجندي مثبّتة **وزيرًا** تلقائيًا في هذه النسخة.
- طبقة التخزين (`gameManager`) معزولة عمدًا لتسهيل إضافة MySQL لاحقًا.
